# 围绕目标写精简提示词

用于写稿或实质改稿。讨论模式已关联项目时先完成本轮上下文刷新；只在当前侧面对话整理，不执行项目任务，也不调用别的模型替自己整理需求。

## 先还原意图

结合整段输入、兼容的旧约束和最新工作证据，确定目标、对象、动作、硬约束、交付与停止边界。去掉口头填充和重复，把强调保留一次。例子只有定义结果或约束时才保留。用户猜测不当事实，助手建议不当已确认需求。

只在证据明确时纠正语音识别术语，不猜模型名、路径、数字或权限。只追问阻碍安全交接的核心目标或范围歧义；普通实施细节留给工作模型。未知事实若正是调查目标，不要求用户先给答案。明确任务或需求足够清楚时本轮主动交稿；“先讨论/暂不交稿/确认后再写”的本轮边界优先。

## 最小充分提示词

按需要组合，不是必须逐项展示的模板：

1. **目标和动作**：第一句说清要完成什么。
2. **必要上下文**：仅保留影响执行的当前状态、对象/位置、关键决定或失败原因。
3. **硬约束**：含兼容旧约束、最新纠正、授权与停止边界。
4. **交付**：用户要拿到的结果或已明确的完成条件。

默认一段或几个短段落。简单任务常可一两句完成，复杂任务只增加不可缺的条件，不设置硬字数。交稿前做一次删减：重复目标和约束合并，同一对话的已知背景省略，普通步骤交执行模型判断。每句问自己：删掉是否会改变结果、范围或关键执行判断？不会就删。提示词外通常只需模型、强度和必要的一句说明，不先写长篇方案再重复到稿内。

同一工作对话已有上下文时，写“基于当前项目/上次结果继续……”并明确本次目标及新增约束即可。重要边界仍需保留。交给全新对话则补足定位、必要背景或可读取的来源；不能假装对方看过侧面对话。

不复制整个聊天、工具日志、模型选型分析或 Skill 流程；不添加泛用角色、思考链要求、机械步骤、无必要的测试/报告/审批、虚构验收指标。选择理由放在提示词外，协作授权放在提示词内。

## 整体交付，按需协作

默认一份整体目标提示词，由执行模型发现实施细节。不要为了让 Luna 适配而删掉困难要求，也不要默认拆成五份让用户分轮派发。用户确实要求逐阶段讨论/确认时保留该边界。

先判断拆分是否有实际收益；简单任务、强耦合任务或协调成本抵消收益时，不写协作段。选主模型带 Luna 时，在可复制提示词内用一两句写明主模型职责、子智能体承担的工作及 GPT-6 Luna / X-High 配置。已知分工写到能执行的程度，未知细节留给主模型；不强行列出所有步骤或固定人数。框外若推荐“两名 Luna 分别查 A/B”，稿内也必须交接这项安排，不能只说“可使用子代理”或省略。详细判断见 [hybrid-delegation.md](hybrid-delegation.md)。

## 修订与检查

返回完整的精简修订稿，保留原目标和兼容条件，不让用户合并补丁。每次同时给完整模型名和明确强度。明确工作请求、已可交接的任务或已有稿的补充纠正，本轮交付；关键未知项标注临时稿及条件性选型，不能只承诺以后写。

对照输入检查：目标正确、约束未丢、没有自加任务、不把未知变事实、停止边界不变。再单独阅读复制区域，确认推荐的必要协作安排完整随稿、与框外一致；单模型任务没有多余分工。若重复之前失败的动作，必须有新依据或方法变化，不能只重新措辞。

## 示例

文档任务：“基于当前存档管理原型和已确认讨论，撰写完整需求文档。自动与手动 APP 存档同等管理，管理页不新建或读取进度；区分现状、目标和待确认规则，说明各操作用途与影响范围。本轮只写文档。”

评估边界：“评估当前页面的信息顺序，提出让阅读更连贯的调整建议。先给建议，暂不修改文件。”

兼容纠正：“优化这段 SQL 的性能，保持结果口径，优先可读性。不要执行查询；返回修改后的 SQL 并说明关键改动。”

整体协作：“完成当前项目的导出功能，沿用已确定的格式和权限要求。可按实际需要让 GPT-6 Luna / X-High 子智能体处理格式适配或既定用例核查；你负责接口与权限判断、分工、整合和最终交付。”

已明确两路只读核查时，可在任务稿内加入：“安排两名 GPT-6 Luna / X-High 子智能体并行只读核查：一名查4位融资成员的数据到达记录，另一名查8位宽度/集中度成员的数据生成记录。你负责统一时间口径、复核关键证据并汇总结论。”人数和类别来自本次任务，不作为通用模板。
